# Factory Testing Guide — Staging Environment

**Audience:** Factory testing team (operators, inspectors, supervisors)
**Environment:** Staging — exact production copy
**Last updated:** 2026-05-02

---

## What this guide is for

The Console MES system has just received an architectural update (the
"Console Inspection Unification"). Before we roll this out to live production,
the factory testing team needs to verify that all shop-floor processes work
correctly on staging.

You'll use **real items, real batches, real employee IDs** — staging is an
exact copy of production. Records you create during testing become real ERP
records (Stock Entries, Quality Inspections, etc.) on the staging instance.
**They do NOT affect live production data**, but they DO consume staging
stock, so don't go overboard with quantities.

## Conventions used in test documents

### Symbols you'll see

| Symbol | Meaning |
|---|---|
| ✅ | Step succeeded as expected |
| ❌ | Step failed — file a bug |
| ⚠️ | Warning — proceed but note the deviation |
| 🔴 | Critical — must work for the test to pass |
| 🟡 | Important — should work but not a blocker |
| 🟢 | Nice-to-have — optional polish |
| 📝 | Tester action: write down a value (e.g., reference ID) you'll need later |
| 🔍 | Verification step: check this in another browser tab |

### Tab references

The guide assumes you have these 4 tabs open and logged in:

| Tab | URL | Purpose |
|---|---|---|
| **Console Dash** | https://console.m.frappe.cloud/dash | Shop-floor entry screens (where you submit) |
| **Console Desk** | https://console.m.frappe.cloud/app | Audit records, transaction logs |
| **Ops** | https://newspp.m.frappe.cloud/app | Verify Stock Entry + Quality Inspection landed |
| **Legacy** | https://sppmaster.frappe.cloud/app | Verify Compound Inspection / DCR landed on Legacy ERP |

When the guide says "open Console Desk → Console Inspection list", switch
to the Console Desk tab and navigate. Don't open new tabs unless instructed.

### Common terms

| Term | What it means |
|---|---|
| **Reference ID** | A 13-digit number (like `1777544406041`) that identifies a single submission across all 3 systems. The Console generates it. **Always copy this** — you'll need it to find the same record on Ops and Legacy. |
| **Mix Barcode** | The compound batch identifier (e.g., `C_26D28X8`). Generated when MB Mixing creates a batch. |
| **SPP Batch No** | Same as Mix Barcode for compounds. Used as the Legacy lookup key. |
| **Lot No** | Production lot identifier (e.g., `LOT-20260502-001`). Generated by Work Planning. |
| **Bridge** | The sync engine that pushes Console submissions to Ops and Legacy in parallel. |
| **Sync Status** | The Console record's view of whether both ERPs accepted the submission. Values: `Pending` → `Partial` → `Success` (or `Failed`). |

## Bug reporting

### When to file a bug

File a bug if any of these happens:

- ❌ The Dash screen shows an error message you don't expect
- ❌ The submission appears to succeed but no record exists on Console Desk
- ❌ The Console record shows `sync_status = Failed` or stays `Partial` for >5 minutes
- ❌ The Ops or Legacy record is missing fields, has wrong values, or doesn't exist
- ❌ A field that should be filled is empty
- ❌ A button doesn't work or the screen freezes
- ⚠️ Anything that "feels wrong" even if it technically completed

### How to file a bug

**Step 1 — Capture the evidence (BEFORE clicking anything else):**

1. **Screenshot the Dash screen** showing the error or wrong state (Cmd+Shift+4 on Mac, PrintScreen on Windows)
2. **Copy the Reference ID** from the result modal (the 13-digit number)
3. **Open Console Desk** → search for the Reference ID → screenshot the **Console Transaction Log** entries
4. **Open Console Desk** → open the parent record (Console Inspection / Console Master Batch Mixing / etc.) → screenshot the full record including the **Payload Snapshot** field at the bottom

**Step 2 — Note the context:**

- What process were you testing? (file name, e.g. `01_compound_inspection.md`)
- Which scenario number? (e.g. "Scenario 2 — Hardness OOR triggers Deviation flag")
- What step did it fail on?
- What did you expect to see?
- What did you actually see?

**Step 3 — File the bug:**

Default destination: **GitHub Issues on `iyyanarr/shree_polymer_console`**
URL: https://github.com/iyyanarr/shree_polymer_console/issues/new

> ⚠️ **Confirm with your supervisor** before first use — they may want bugs
> filed in a different system (Slack channel, Google Doc, etc.). This guide
> defaults to GitHub Issues but the bug-filing destination is configurable.

**Bug report template (paste into the Issue body):**

```markdown
## Process under test
- Document: `01_compound_inspection.md`
- Scenario: 2 — Hardness OOR triggers Deviation flag
- Step that failed: 4

## Reference ID
1777544406041

## What I expected
After scanning a hardness reading of 55 (below the spec minimum of 60),
the Console should mark the inspection as Rejected and route it to the
Compound Deviation queue for QM review.

## What actually happened
The Dash screen showed "Submission successful" but the Console
Transaction Log shows Legacy = Failed with error:
"The Stock Entry reference not found..!"

## Evidence
- [Screenshot 1] Dash screen at the moment of submit
- [Screenshot 2] Console Transaction Log entries
- [Screenshot 3] Console Inspection record with payload_snapshot expanded
- [Screenshot 4] Legacy Bridge Log on sppmaster.frappe.cloud (if applicable)

## Tester
Name: _______________
Date/Time: 2026-05-02 14:30 IST
Site (browser URL): https://console.m.frappe.cloud/dash
```

## Escalation ladder

| Severity | Examples | Who to notify |
|---|---|---|
| 🟢 **Low** — Cosmetic | Misaligned button, wrong label, unclear tooltip | File GitHub issue |
| 🟡 **Medium** — Wrong data | A field has a typo'd value, listview shows extra columns | File GitHub issue + flag in daily standup |
| 🔴 **High** — Submission fails | Bridge sync fails, record doesn't land on Ops/Legacy, sync_status stuck Partial | File GitHub issue + WhatsApp the dev team immediately |
| 🚨 **Critical** — Data corruption | Wrong batch number, stock balance off, can't cancel a record, two records with same Reference ID | STOP TESTING. Call the dev team. Do not submit any more records until cleared. |

## What success looks like

By the end of this testing cycle, you should be able to say:

✅ "Every shop-floor submission I made on staging landed correctly on Console, Ops, AND Legacy."

✅ "When something failed, I could find the error in Console Transaction Log within 30 seconds."

✅ "I can run a real shift on staging without thinking about which system the data goes to — it just works."

If we can't say all three, we don't roll out to live production yet.
