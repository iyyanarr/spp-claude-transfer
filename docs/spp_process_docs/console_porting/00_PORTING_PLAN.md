# Console DocType Porting Plan — MB Mixing → Moulding Production Entry

**Goal:** Port every doctype the production chain needs onto Console as local-cache-first records, so the Console becomes the system of record and the Bridge can fan out to Legacy + Ops in parallel.

**Source of truth:** `/Users/alphaworkz/frappe-bench/spp_process_docs/*_Documentation.md` per doctype.

**Architecture decision (assumed — confirm):**
- Console is local-first: every shop-floor submission writes a `Console *` record immediately, then the Bridge syncs to Legacy + Ops in parallel.
- Console owns barcode/lot/serial generation where possible (so identity is consistent across both ERPs).
- Legacy `Job Card` and `Work Order` are NOT mirrored — Console references them by name only after Work Planning generates them via the Bridge.
- Inspection Entry (Line/Patrol) IS mirrored on Console because MPE submission depends on its existence.

## Conventions for every Console doctype

Every new `console_*` doctype MUST include this block of standard fields (otherwise the Bridge pipeline can't pick it up):

| Field | Type | Purpose |
|---|---|---|
| `process_code` | Data (read-only) | Set in `before_insert` to e.g. `MASTER_BATCH_MIXING`, `BLANKING_DC_ENTRY`. Used by `process_template` lookups. |
| `reference_id` | Data (read-only, unique) | The 13-digit `Date.now()` ID generated by Dash; ties Console row to both Legacy and Ops sync logs. |
| `ops_reference` | Data | Name of the resulting Ops document (e.g. `MES-LOG-2026-01383`). Filled by Bridge on success. |
| `legacy_reference` | Data | Name of the resulting Legacy document. Filled by Bridge on success. |
| `sync_status` | Select: `Pending`/`Partial`/`Success`/`Failed` | Read-only summary set by Bridge. |
| `target_system` | Select: `Both`/`Legacy`/`Ops` | Defaults to `Both`; can be narrowed for testing. |
| `submitted_by` | Link (Console User) | The Console user who pressed Submit. |
| `posting_date` | Date | The shop-floor effective date (NOT creation date — supports backdating). |
| `posting_time` | Time | Same. |
| `attachments` | Long Text (JSON array) | URLs from `AttachmentSection`. |
| `remarks` | Small Text | Free-text notes. |
| `payload_snapshot` | Long Text (JSON) | Full payload as submitted, for debugging/replay. |
| `error_log_summary` | Small Text | Set by Bridge if either leg fails (first traceback line). |

Every doctype is **Submittable** (`is_submittable: 1`), naming series `<PROCESS_CODE_PREFIX>-.YYYY.-.#####`, and has `track_changes: 1`.

Every parent doctype's controller (`.py`) MUST implement:
- `before_insert` — set `process_code`
- `validate` — schema-level invariants only (no remote calls)
- `on_submit` — emit a `Console Transaction Log` Pending entry
- A whitelisted `apply_bridge_result(target, status, remote_name, error)` method the Bridge calls back to update `ops_reference` / `legacy_reference` / `sync_status` / `error_log_summary`.

## Definition of Done — every doctype

A doctype is "done" only when ALL of:

- [ ] Directory at `shree_polymer_console/shree_polymer_console/doctype/<name>/`
- [ ] `<name>.json` with all standard fields + process-specific fields
- [ ] `<name>.py` with controller class extending Frappe `Document`, implements the standard hooks listed above
- [ ] `__init__.py` (empty)
- [ ] `test_<name>.py` with at minimum one `test_create_and_submit` and one `test_validate_required_fields`
- [ ] Naming series registered in `Property Setter` or via the doctype's `autoname`
- [ ] Listed in `modules.txt`'s "Shree Polymer Console" module (auto-handled if path is correct)
- [ ] Permissions: `System Manager`, `Console Operator`, `Quality Inspector`, `Quality Manager` rows configured per doctype role matrix
- [ ] `bench --site sppconsole-dev.local migrate` runs without error
- [ ] Created via `frappe.new_doc` programmatically — `insert()` succeeds without ValidationError
- [ ] `process_template_seeder.py` registers a `Console Process Template` row for it (so the Dash can route to it)
- [ ] `legacy_bridge_seeder.py` registers a `Legacy Sync Mapping` row that maps the Console doctype → Legacy doctype
- [ ] One end-to-end test: submit from Dash, both Legacy + Ops sync logs land Success, Console record gets `sync_status=Success`

## What I won't do as part of this plan

- Rewrite the Bridge sync logic — it stays defense-in-depth as discussed; only mapping tables get updated per doctype.
- Touch Ops/Legacy doctype definitions — those are upstream and out of scope.
- Retrofit the 7 already-shipped Dash screens beyond their existing payload contracts — Wave 1 lands what they already send.
- Mirror Job Card or Work Order — see architecture note above; they're referenced by name only.
